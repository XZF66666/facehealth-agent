# 脉镜智康：个人健康管理智能体 App 项目工作总结

## 一、项目概述

脉镜智康是一款面向个人日常健康管理的 Android App Demo。项目以低打扰式人脸视频采集为入口，在用户明确授权后，通过手机前置摄像头获取短时面部视频，在手机本地完成心率、呼吸率和 HRV 趋势代理指标估计；系统将检测结果与睡眠、压力、症状及近 7 天历史数据组合，通过规则引擎和大语言模型 Agent 完成趋势分析、压力与疲劳状态评估、风险提示及健康建议生成。

项目形成了“视频感知—本地计算—数据记录—趋势分析—智能建议”的个人健康管理闭环。当前产品定位为健康趋势管理与风险提示工具，不用于疾病诊断或替代专业医疗设备。

## 二、个人完成的主要工作

### 1. Android 端产品流程重构

- 将原有生理信号测量能力保留并整合为完整业务流程：隐私授权、视频录制、本地分析、状态填写、结果记录、趋势展示和智能建议。
- 将检测入口、健康看板、周报和对话助手整合为统一的个人健康管理 App。
- 增加首页、检测、趋势、助手和“我的”底部导航，降低主要功能的操作层级。
- 优化录制结束后的页面跳转和失败处理，避免分析空白页及结果无法返回的问题。
- 分析完成后将结果保存到本地数据库，并回到首页展示最新健康数据。

### 2. App 界面与交互优化

- 重新设计首页健康看板，集中展示心率、呼吸率、HRV、压力、疲劳和 7 天趋势。
- 统一首页、录制页、分析页、状态填写页、周报页和对话助手的视觉语言。
- 优化摄像头预览区域和人脸引导框，提示用户将完整头部与下巴保持在框内。
- 将录制时长调整为 15 秒，并增加倒计时、录制进度、视频清晰度和操作状态反馈。
- 为分析页增加真实处理阶段、有效人脸帧数量、进度条、重新分析和重新录制入口。
- 为状态填写页增加保存状态，防止重复点击。
- 对话助手改为左右消息气泡，支持加载动画、失败重试、清空会话和流式内容展示。
- 周报增加真实 7 天折线图，可切换查看心率、HRV、压力和疲劳变化。

### 3. 本地生理信号提取链路

当前生理信号处理在 Android 手机本地完成，主要流程如下：

1. 使用 Camera2 和 MediaRecorder 录制 15 秒、30 fps、最高 1920×1080 的前置摄像头视频。
2. 使用 MediaPipe Face Landmarker 检测人脸关键点。
3. 根据关键点划分额头、左脸颊和右脸颊三个皮肤感兴趣区域。
4. 计算各区域逐帧 RGB 均值，使用三个区域的绿色通道平均值构造原始 rPPG 时序信号。
5. 对信号进行标准化，并在心率与呼吸率频带内搜索主频。
6. 将频率转换为心率和呼吸率，生成 HRV 趋势代理指标。
7. 根据心率、呼吸率和 HRV 趋势，通过本地规则计算压力及疲劳分数。

当前实现证明了普通手机摄像头进行非接触式健康感知的可行性，但仍属于 Demo 算法。现有 HRV 是基于颜色波动构造的趋势代理值，并非基于逐搏间期计算的标准 RMSSD 或 SDNN，因此项目报告中不将其描述为医疗级 HRV。

### 4. 本地数据管理与趋势分析

- 使用 SQLite 保存每日心率、呼吸率、HRV、压力、疲劳、睡眠、症状和用户备注。
- 实现近 7 天数据读取、平均值计算和异常天数统计。
- 根据今日数据与个人历史基线进行比较，减少仅依赖统一正常范围带来的偏差。
- 在首页和周报中通过图表展示连续变化，突出个人纵向趋势，而不是单次检测结果。

### 5. FastAPI 后端与 Agent 建设

在仓库的 `backend/` 目录建立独立 FastAPI 后端，完成以下接口：

- `POST /api/agent/analyze`：生成今日状态分析。
- `POST /api/agent/weekly-report`：生成 7 天健康周报。
- `POST /api/agent/chat`：提供健康助手多轮对话，支持 JSON 和 SSE 流式输出。
- `DELETE /api/agent/chat/{conversation_id}`：清理指定会话记忆。

后端负责组合今日指标、7 天历史、睡眠、主观压力和症状。系统先由规则引擎识别异常指标和风险等级，再将结构化上下文交给大模型生成通俗解释与健康建议，避免完全依赖大模型自由判断。

### 6. 阿里云大模型接入

- 在服务器 `.env` 中配置阿里云 DashScope 兼容接口，模型密钥只保存在后端，不写入 Android App。
- 接入通义千问模型，完成今日分析、周报、普通聊天和流式聊天测试。
- 为后端增加请求超时、模型异常处理、日志记录和本地降级结果。
- 验证多轮对话能够复用同一个 `conversation_id`。

### 7. Android 与后端联调

- Android Debug 构建通过 `adb reverse` 访问本地 `http://127.0.0.1:8100`；Release 使用 HTTPS 占位地址。
- 今日分析、周报和聊天读取超时提高到 120 秒，适应大模型生成耗时。
- 在 `AgentApiClient` 中实现真正的 SSE 事件解析，按 `meta`、`delta`、`done` 和 `error` 增量处理响应。
- Android 收到每个 `delta` 后立即追加到当前助手气泡，不再等待完整回复。
- 将后端返回的 `conversation_id` 保存到 SharedPreferences，在 App 重启或重新进入助手页面后继续复用。
- 清空会话时同步删除本地会话 ID，并调用后端接口清理服务端记忆。
- 配置 Windows 专用网络 TCP 8100 入站规则，完成 Android 手机到 FastAPI 后端的局域网连通验证。
- 完成 Android Debug APK 编译、真机安装和应用进程启动验证。

## 三、系统技术架构

系统采用端云协同架构：

```text
Android 前置摄像头
    ↓
MediaPipe 人脸关键点与皮肤 ROI
    ↓
手机本地 rPPG 信号处理
    ↓
心率 / 呼吸率 / HRV趋势 / 压力 / 疲劳
    ↓
SQLite 本地历史数据与 7 天趋势
    ↓
FastAPI 规则引擎
    ↓
阿里云通义千问健康 Agent
    ↓
今日分析 / 周报 / 多轮对话 / 健康建议
```

面部视频和原始颜色信号默认在手机本地处理，后端接收结构化健康指标及用户主动填写的信息，兼顾响应速度、隐私保护和模型能力。

## 四、项目创新点

1. **低打扰式非接触感知**：使用普通手机前置摄像头完成日常生理趋势采集，不要求额外穿戴设备。
2. **本地隐私计算**：人脸视频、生理信号提取和历史记录主要在手机本地完成。
3. **规则引擎与大模型协同**：先进行确定性异常筛查，再由大模型负责解释和建议生成。
4. **个人基线趋势管理**：通过连续 7 天数据分析用户自身变化，而不是只给出一次性数值。
5. **多轮健康 Agent**：Agent 能够组合今日检测、历史趋势、睡眠、压力和症状，并通过会话 ID 保持上下文。
6. **端云可扩展架构**：后续可以加入端侧轻量 rPPG 深度学习模型、信号质量模型和经验证的血压趋势模型。

## 五、当前成果与验证情况

- 已跑通 15 秒视频录制和本地生理信号分析流程。
- 已实现检测结果保存、首页看板和 7 天趋势图。
- 已实现今日智能分析、健康周报和多轮健康对话。
- 已实现阿里云大模型的普通输出与 SSE 流式输出。
- FastAPI 自动化测试共 6 项通过。
- Android Debug APK 编译成功并安装至真实 Android 手机。
- 手机通过局域网访问后端健康接口成功，后端返回模型配置有效。

当前测试主要验证功能完整性与工程可运行性，尚未完成与 ECG、指夹式血氧仪或标准血压计的系统性精度对照实验，因此不能宣称达到医疗器械精度。

## 六、现有不足

- 15 秒视频仅抽取 60 帧进行分析，有效分析采样率约 4 Hz，限制了高心率和逐搏波形估计。
- 当前算法缺少完整的去趋势、带通滤波、窗函数、运动补偿和信号质量指数。
- 当前主要使用绿色通道，尚未集成 POS、CHROM 等抗光照和抗运动算法。
- 呼吸率观测时间较短，低频估计容易受曝光和头部运动影响。
- HRV 为趋势代理指标，尚未基于逐搏间期计算 RMSSD。
- 压力和疲劳分数目前属于规则评分，尚未经过临床数据训练与验证。
- 当前局域网后端地址为固定 IP，正式部署时需要 HTTPS 域名、身份认证和数据库持久化。

## 七、后续工作计划

### 第一阶段：提高 rPPG 精度

- 使用完整 30 fps 帧流和真实时间戳，不再只抽取 60 帧。
- 增加去趋势、带通滤波、Hann 窗、Welch 功率谱和峰值追踪。
- 实现 GREEN、POS、CHROM 多算法融合，根据 SNR 自动选择结果。
- 增加皮肤掩膜、头部运动补偿、曝光检测和多 ROI 一致性判断。
- 建立信号质量指数 SQI，信号不合格时拒绝输出结果。
- 从 rPPG 波形检测脉搏峰，计算 PRV/RMSSD，并将快速心率与长时 HRV 测量模式分开。

### 第二阶段：端侧轻量深度学习

- 使用 PyTorch 训练轻量 1D TCN 或深度可分离时序网络。
- 输入多 ROI RGB 时序信号，输出干净 rPPG 波形、心率、呼吸率和 SQI。
- 导出 ONNX，使用 ONNX Runtime Android 在手机端推理。
- 通过 FP16、INT8 量化、知识蒸馏和算子裁剪控制模型体积、内存和延迟。
- 保留传统 POS/CHROM 算法作为模型失败时的降级方案。

### 第三阶段：血压趋势模型

- 使用高采样率 rPPG 波形、波形导数、心率、PRV、SQI 和用户基础信息构建血压模型。
- 采用轻量 1D ResNet/TCN 输出收缩压、舒张压和预测不确定度。
- 引入上臂式血压计进行首次个体校准，采用“个人基线 + 模型预测变化量”的方式降低跨用户误差。
- 使用同步面部视频、rPPG 和标准血压参考值建立自有数据集。
- 严格按照受试者划分训练集和测试集，报告 MAE、RMSE、相关系数及 Bland–Altman 一致性。
- 血压功能在完成充分验证前仅展示趋势和研究结果，不用于高血压诊断或用药建议。

### 第四阶段：完善生产级后端

- 将固定局域网地址替换为 HTTPS 域名。
- 增加用户认证、数据加密、限流、审计日志和隐私撤回机制。
- 将内存会话升级为 Redis 或数据库持久化会话。
- 增加 Agent 工具调用、个性化记忆和健康计划跟踪。
- 建立模型版本管理、提示词版本管理和安全评测流程。

## 八、总结

本项目已经从单一的人脸视频生理信号测量 Demo，发展为具备移动端采集、本地信号分析、历史数据管理、趋势可视化、规则风险筛查和大模型健康 Agent 的完整原型。项目的工程闭环已经跑通，端云接口和真机联调均已完成。

下一阶段的重点不再是单纯增加页面或功能，而是建立可量化的信号质量体系、同步参考设备实验和跨用户精度评测，在此基础上部署轻量 rPPG 模型并研究个体校准血压趋势模型，使项目从“功能可演示”逐步提升为“算法可验证、结果可解释、部署可落地”的个人健康管理智能体。
